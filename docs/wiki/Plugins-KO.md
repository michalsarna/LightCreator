# 플러그인

플러그인은 프로그램을 바꾸지 않고 LightCreator에 기능을 더합니다: **클립아트, 기계 프리셋, 번역, 다른 파일 형식의 가져오기 기능, 도형 생성기, G-code 포스트프로세서.** 플러그인은 LightCreator, MillCreator, PenCreator가 공유합니다. 플러그인은 공유 데이터 폴더(`baseCreator`) 안의 `plugins` 폴더에 있으며, 각 프로그램은 자신에게 맞는 부분을 사용합니다.

**설정 → 플러그인…**(Settings → Plugins…)은 창을 엽니다: `.zip`에서 플러그인 설치, 플러그인 켜기와 끄기, 제거, 폴더 열기, 그리고 설정이 있는 플러그인의 설정. 선택할 것이 있는 모든 플러그인(**포스트프로세서**(postprocessor))은 오른쪽 패널에 자체 탭이 있으며, 그곳에서 다음 G-code 내보내기에 사용할 것을 선택합니다.

* **가져오기 기능:** **파일 → 가져오기 → 플러그인으로 가져오기…**(File → Import → Import with a plugin…), 끌어다 놓기, 또는 플러그인이 읽는 확장자의 파일을 열기(Open). 도형이 도면에 추가됩니다(선택된 상태, 실행 취소 한 번).
* **생성기:** **삽입 → 도형 생성…**(Insert → Generate shape…) (**파일 → 가져오기 → 도형 생성…**(File → Import → Generate shape…)도 가능)은 생성기의 양식(숫자, 스위치, 텍스트, 목록)을 보여 주고 생성기가 만든 도형을 추가합니다.
* **포스트프로세서:** 플러그인의 탭에서 하나를 선택하면 **G-code 내보내기…**(Export G-code…) (**G-code 저장**(Save G-code) 버튼, **파일 → 내보내기 → G-code 내보내기…**(File → Export → Export G-code…), **레이저 → G-code 내보내기…**(Laser → Export G-code…))와 **G-code 미리 보기**(Preview G-code)가 프로그램을 그 포스트프로세서에 통과시킵니다. 포스트프로세서를 전환하면 G-code 텍스트 탭이 다시 만들어집니다. 포스트프로세서는 G-code 줄만 바꿀 수 있습니다. 컨트롤러 명령(`$…`, `~`, `!`, `?`)이거나 제어 문자가 포함된 줄은 거부되며 아무것도 저장되지 않습니다. 작업을 기계로 바로 보내는 것(**START**, **기계 → 작업 시작**(Machine → Start job))은 포스트프로세서를 거치지 않습니다.
* 플러그인의 프리셋과 데이터 파일(`mill-tools`)은 LightCreator에서 사용하지 않습니다. LightCreator는 클립아트, 가져오기 기능, 생성기, 포스트프로세서를 사용합니다.

**G-code tools(및 모든 포스트프로세서) 사용하기, 단계별 안내.** 1. **설정 → 플러그인…** → **공식 플러그인**(Official plugins) → **G-code tools** 설치(또는 **zip에서 플러그인 설치…**(Install plugin from zip…)). 2. 오른쪽 패널의 다른 탭들 뒤에 **G-code tools**라는 탭이 나타납니다(패널이 접혀 있으면 좁은 띠에). 3. 탭을 열고 **줄 번호 매기기 (N10, N20, …)**(Number the lines (N10, N20, …)) 또는 **주석 제거**(Remove comments)를 선택합니다. **없음**(None)은 다시 끕니다. 4. **G-code 내보내기…** (LightCreator의 **레이저**(Laser) 메뉴, 다른 프로그램의 밀링(Milling) / 플롯(Plot) 메뉴, 또는 **G-code 저장** 버튼)가 이제 처리된 파일을 기록합니다. 상태 표시줄에 어떤 포스트프로세서가 사용되었는지 표시됩니다. **Start**로 시작한 작업은 변경 없이 전송되며, G-code 뷰어는 파일을 기록된 그대로 보여 줍니다.

**안전.** 플러그인 스크립트(Rhai)는 파일, 네트워크, 시스템, 기계에 접근할 수 없는 샌드박스에서 시간과 메모리 제한을 두고 실행됩니다. 그렇더라도 플러그인은 기계에 무엇을 지시할지 결정하는 다른 사람의 코드입니다. 신뢰하는 플러그인만 설치하고, 새 포스트프로세서의 G-code는 기계에서 실행하기 전에 살펴보십시오.

## 공식 플러그인

**설정 → 플러그인… → 공식 플러그인**은 [baseCreator-plugins](https://github.com/michalsarna/baseCreator-plugins) 저장소에서 관리되는 공식 플러그인 목록을 보여 줍니다. **업데이트 확인**(Check for updates)을 눌러 불러오십시오. 다른 프로그램용 플러그인(*대상: …*(For: …)으로 표시)을 포함해 *모든* 플러그인이 나열됩니다. **설치**(Install)는 공식 사이트에서 플러그인을 다운로드해(체크섬 확인) 모든 프로그램이 공유하는 플러그인 폴더에 넣습니다. 목록에 더 새로운 버전이 있으면 **업데이트**(Update)가 나타나며, 마우스를 올리면 변경 내역이 보입니다. 사용 중인 프로그램보다 새로운 프로그램이 필요한 플러그인은 표시되지만 제공되지 않습니다. 프로그램 시작 시 업데이트 확인은 **켜져** 있습니다(끄려면 *시작 시 플러그인 업데이트 확인*(Check for plugin updates at start)의 체크를 해제). 오래된 플러그인이 있으면 창이 그 목록을 **모두 업데이트**(Update all), **플러그인**(Plugins), **나중에**(Later)와 함께 보여 줍니다. 사용자가 클릭하지 않으면 아무것도 설치되지 않습니다.

직접 플러그인을 작성해 목록에 보내는 방법: 플러그인 저장소의 템플릿이 포함된 [작성자 안내서](https://github.com/michalsarna/baseCreator-plugins/blob/main/docs/GUIDE.md)를 참고하십시오. 문제와 아이디어는 그 저장소의 이슈로 보내 주십시오.

플러그인 작성 방법(매니페스트, 양식, 스크립트 함수, 예제): [baseCreator의 PLUGINS.md](https://github.com/michalsarna/baseCreator/blob/main/docs/PLUGINS.md).

여러 포스트프로세서를 동시에 켤 수 있습니다. 플러그인 탭에서 체크하면 **체크한 순서대로** 실행되며(한 포스트프로세서의 줄이 다음으로 전달됨), 상태 표시줄에 `+`로 연결된 이름이 표시됩니다. **없음**은 모두 끕니다.
